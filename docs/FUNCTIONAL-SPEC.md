- 대조 문서: `docs/PRD.md`
- 기준 코드: `app/` (Next.js 16 App Router / React 19 / Drizzle + Supabase / Tailwind v4)

## 0. 이 문서의 성격

`docs/PRD.md`가 "무엇을 왜 만들 것인가"를 정의한다면, 이 문서는 **이미 만들어진 약 60개 화면에서 실제로 확정된 기능·입력값·계산식·상태값**을 추출해 정본으로 고정한 것이다.

각 기능에는 구현 등급을 표기한다.

| 등급 | 의미 |
|---|---|
| **A** | UI + DB/서버액션 연동 완료. 동작함 |
| **B** | UI 완성 + 도메인 로직(계산식·검증) 확정, 저장소만 목업(localStorage 또는 setTimeout) |
| **C** | UI만 존재. 핸들러 없음 / `alert()` 스텁 |
| **D** | 라우트는 있으나 네비게이션에서 도달 불가(고아) 또는 데드코드 |

## 1. 서비스 범위

### 1.1 3개 애플리케이션

| 영역 | 경로 | 대상 | 상태 |
|---|---|---|---|
| **공개 홈페이지** | `(site)/` | 잠재 고객 | 정적 완성 (A/C) |
| **광고주 플랫폼** | `(platform)/marketing/**` | 사업자·셀러 | UI 완성, 대부분 B |
| **운영자 콘솔** | `(platform)/admin/**` | 내부 운영자 | A (실 DB 연동) |

### 1.2 사용자 역할 (`user_role` enum)

| 역할 | 값 | 접근 범위 | 구현 |
|---|---|---|---|
| 광고주 | `advertiser` | `/marketing/**` (가입 시 기본값) | A |
| 공급자 | `supplier` | 포털 없음. 어드민이 대신 관리 | 스키마만 |
| 관리자 | `admin` | `/admin/**` | A |

> **갭**: 세분 권한(퍼미션)이 없다. 운영자/정산담당/CS를 구분하려면 역할 확장 필요.

### 1.3 레거시 영역 (정리 대상)

`(platform)/dashboard/**`(프로필·포트폴리오·블로그)와 `/[username]` 공개 프로필은 **개인 셀프 브랜딩 시절의 유물**이다. 서버액션은 완성돼 있으나 페이지가 빈 배열을 넘겨 읽기 경로가 끊겨 있고, 인증 가드도 없다. `users`/`profiles`/`projects`/`posts` 테이블도 이 영역 전용이다.

**결정 필요**: 삭제 / 보류 / B2B용으로 재활용(사업자 프로필) 중 택1.

## 2. 서비스 카탈로그 (구현으로 확정된 상품 체계)

프론트엔드가 정의한 실제 판매 상품군은 PRD의 9개 `product_type`보다 세분화되어 있다.

```
1. 리워드 마케팅   reward/{place, shopping, coupang, google}  + place/guaranteed
2. 리뷰·체험단     review/place/{blog-reporter, receipt, visitor, reservation, blog-experience}
                   review/shopping/{product-experience, blog-reporter, blog-experience}
3. 통합 순위관리   rank/{place, shopping, coupang}            ← 무료 부가기능
4. 퍼포먼스 광고   ads/{naver-cpc, naver-cpc-refund, meta}     ← 상담형(대행)
5. 바이럴          community/cafe                              ← 상담형(대행)
6. 콘텐츠 제작     content/{image, branding, homepage, detail, video} ← 상담형(대행)
7. 커뮤니티        community/board, notices
8. 마이            my/{campaigns, charge}, cart, report, support
```

### 2.1 판매 모델 3종

| 모델 | 대상 | 흐름 | 결제 |
|---|---|---|---|
| **셀프 주문형** | 리워드, 리뷰·체험단 | 상품 선택 → 캠페인 설정 → 즉시 결제/장바구니 | 포인트 차감 |
| **상담형** | 광고대행, 바이럴, 콘텐츠 | 랜딩 열람 → 문의 접수 → 오프라인 계약 | 별도 |
| **무료 부가** | 순위관리, 커뮤니티, 리포트 | 로그인 후 상시 이용 | 없음 |

> **결정 필요 (PRD 미해결질문 #1)**: 구현은 **선불 포인트 차감 단일 모델**로 이미 수렴했다. 건별 PG 결제는 어디에도 없음. 이대로 확정할 것을 권장.

## 3. 기능 정의

### FR-AUTH — 인증·계정

| ID | 기능 | 정의 | 등급 |
|---|---|---|---|
| AUTH-01 | 광고주 회원가입 | 이메일/비밀번호. Supabase `auth.signUp` + 동일 id로 `public.users` insert(role=advertiser). 성공 시 `/marketing` | **A** |
| AUTH-02 | 광고주 로그인 | `signInWithPassword`. 쿠키 세션 | **A** |
| AUTH-03 | 로그아웃 | `signout()` 액션 존재. **UI 버튼에 미연결** (헤더/사이드바/어드민 모두) | **C** |
| AUTH-04 | 관리자 로그인 | `/admin/login` → 로그인 후 `users.role='admin'` 검증, 아니면 강제 `signOut` | **A** |
| AUTH-05 | 관리자 부트스트랩 | `BOOTSTRAP_ADMIN_EMAILS`(하드코딩 이메일)는 자동 admin 승격 | **A** ⚠️ 운영 전 제거 |
| AUTH-06 | 라우트 보호 | `proxy.ts`가 no-op 패스스루. 보호는 레이아웃 `requireAdmin()` + 서버액션 가드에만 의존. `/marketing/**`, `/dashboard/**`는 **가드 없음** | **미구현** |
| AUTH-07 | 소셜 로그인 / 비밀번호 재설정 | 없음 | 미구현 |

**필수 보강**: AUTH-06(`/marketing/**` 미로그인 접근 차단), AUTH-03.

## 5. 비즈니스 규칙 정본 (계산식 모음)

```
리워드 주문금액   = 일 작업량 × 매체 단가
리워드 연장금액   = 일 작업량 × 연장일수 × round(기존 주문금액 / 기존 일작업량)
리뷰 주문금액     = 유형 단가 × (발행일수 × 일발행량)  또는  유형 단가 × 모집인원
포인트 충전 입금액 = floor(요청 포인트 × 1.1)              // 부가세 10%
광고비 환급액     = round(월 집행액 × 요율)                // 10%/7%/5%/3%/0%
캠페인 진행률     = round(완료건수 / 총건수 × 100)
보장형 진행률     = min(순위 5위 이내 유지일수 / 25 × 100, 100)
```

**제약 규칙**
- 최소 충전 10,000P
- 리워드 최소 구동 3일, 연장 시 일 작업량 최소 10 (10 단위)
- 리뷰 발행 일수 1~7일
- 순위 조회 상한 300위
- 리뷰 수정 요청 시 키워드 변경 불가
- 당일 접수 마감 13:30
