### PT-01/02 유상·무상 분리

잔액의 **정본은 `credits` 원장**이다. `users.creditBalance` / `users.freeBalance` 는 목록 화면용 캐시이며,
원장을 다시 더해 덮어쓴다(증감 연산을 하지 않는다).

```
creditBalance = Σ delta                      총 잔액
freeBalance   = Σ delta where kind='free'    무상 잔액
환불 가능액    = creditBalance − freeBalance   유상 잔액 (PT-01 / PT-07)
```

rev.11 이전 코드는 `users` 잔액만 따로 증감시켜 원장과 어긋나 있었다. 고객 화면은 원장 합계를,
어드민 화면은 `users` 컬럼을 읽어 같은 회원의 잔액이 화면마다 다르게 보였다.

- 기록은 `lib/points.ts` 의 `grantCredit` / `spendCredit` / `revokeCredit` 만 거친다
- 캐시 복구는 `scripts/backfill-credit-kind.mts` (기본 미리보기, `--apply` 로 반영)

### CS-02/03 공휴일

`holidays` 테이블에 공공데이터 API 결과를 연 단위로 캐시한다. 조회 실패 시 캐시 값을 쓴다.
`policy.ts` 에 연도별로 손으로 적어 둔 배열을 대체한다(매년 갱신이 필요해 방치되면 틀린 값이 된다).

의존: PT-10 환불 영업일 7일 · HD-01 담당자 배정 영업일 1일 · PU-02 예상 집행일.

## 알려진 문제

**`src/lib/policy.ts` 가 초안 기준이라 rev.11 과 충돌한다.** 고객 화면에 폐기된 내용이 노출 중이다.

- 추천 요율 표 **5% / 5% / 3%** — RF-00 에서 일반 회원 코드 발급 자체가 폐지됨
- **PV-02 "대행사 코드로 가입하면 자동 소속"** — AG-05 에서 소속 개념이 폐기됨
- PT-01 문구에 "추천 적립분"이 남아 있음
- 환불 체크리스트가 1단계 — PT-11 의 "접수 시 / 송금 직전" 2단계 구조가 빠짐
- A-03 알림 채널표에 폐기된 "추천 보상 회수" 행이 있고, CP-03(쿠폰 → 카카오톡 채널)이 반영 안 됨

**`drizzle.__drizzle_migrations` 테이블이 없다.** 지금까지 마이그레이션을 실행한 적이 없고 전부 `db:push` 로만
반영해 왔다. 그래서 `drizzle/` 의 마이그레이션 파일이 실제 DB보다 뒤쳐져 있다
(`admin_cart_items` · `purchase_orders` · `rank_memberships` · `products.cost_price` 가 파일에 없다).
