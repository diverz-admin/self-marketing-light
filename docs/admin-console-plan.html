01기획 배경

현재 어드민은 6개 화면 모두 실 DB에 연동된 완성 상태입니다. 문제는 커버 범위입니다. 정의서가 정의한 광고주 기능 중 운영자 손이 닿아야 정상 작동하는 것들이 어드민에 없습니다.

02설계 원칙

1. 처리할 일이 먼저, 조회는 나중에

운영자의 하루는 "오늘 뭘 처리해야 하지?"로 시작합니다. 대시보드는 지표판이 아니라 작업 큐여야 합니다. 승인 대기 4건, 입금 확인 2건, 미답변 문의 3건이 숫자가 아니라 클릭 가능한 할 일로 보여야 합니다.

2. 목록에서 벗어나지 않고 처리한다

검수 · 승인은 반복 작업입니다. 행을 클릭하면 우측 드로어가 열려 상세를 보여주고, 처리 후 드로어만 닫힙니다. 별도 상세 페이지로 이동하면 목록 위치와 필터가 날아가 20건 처리에 40번 뒤로 가기를 하게 됩니다.

3. 상태를 바꾸면 사유가 남는다

지금은 어떤 상태에서 어떤 상태로든 이동할 수 있고 누가 바꿨는지 기록이 없습니다. 정의서 7장의 감사성 요구를 지키려면 모든 상태 변경에 행위자 · 시각 · 사유가 함께 저장되어야 합니다. 금전이 움직이는 변경(환불, 크레딧 조정)은 사유를 필수로 합니다.

4. 돈은 두 번 확인한다

환불 · 크레딧 조정 · 정산 확정은 확인 모달에서 금액을 다시 보여주고 실행합니다. 되돌릴 수 없는 작업에 실수 여지를 남기지 않습니다.

5. 목록은 반드시 서버에서 자른다

현재 6개 화면 전부 전건을 로드해 클라이언트에서 필터링합니다. 캠페인이 1만 건이 되면 화면이 열리지 않습니다. 모든 목록에 서버 페이지네이션 · 검색 · 정렬을 적용합니다.

04공통 패턴

목록 화면 규격

모든 목록 화면은 위에서 아래로 같은 구조를 따릅니다.

① 요약 카드      2~4개. 이 화면에서 처리해야 할 건수를 먼저
② 상태 탭        건수 배지 포함. 기본 선택 = 처리 대기 상태
③ 검색 · 필터    검색어 + 기간 + 부가 필터. URL 쿼리에 반영
④ 테이블         50건 / 페이지 · 서버 정렬
⑤ 페이지네이션    총 건수 + 페이지 이동
  • 필터 상태는 URL에 담습니다. 새로고침해도 유지되고, 운영자끼리 링크로 공유할 수 있습니다.
  • 기본 정렬은 오래된 순. 처리 대기 목록에서 최신순은 오래된 건을 영원히 방치시킵니다.
  • 빈 상태는 "데이터 없음"이 아니라 "처리할 건이 없습니다"로 씁니다.

상세 드로어

행 클릭 시 우측에서 폭 560px 패널이 열립니다. 구성은 요약 → 상세 정보 → 이력 → 액션 순서입니다. 액션 버튼은 패널 하단에 고정해 스크롤과 무관하게 접근할 수 있게 합니다.

목적

신규 접수된 캠페인을 순서대로 승인 · 반려한다. 캠페인 관리가 전체 조회용이라면 검수 큐는 처리용이다. 운영자가 하루를 시작하는 화면.

왜 캠페인 관리와 분리하나

목적이 다릅니다. 캠페인 관리는 "이 광고주 캠페인 어떻게 됐지?"를 찾는 조회 화면이고, 검수 큐는 "대기 건을 0으로 만든다"는 소진 화면입니다. 한 화면에 섞으면 탭 전환과 필터 초기화가 반복됩니다.

06상태 전이 규칙

현재 문제

setCampaignStatus가 어떤 상태에서 어떤 상태로든 전환을 허용합니다. 완료된 캠페인을 초안으로 되돌릴 수 있고, 환불된 건을 진행중으로 바꿀 수 있습니다. 서버액션에서 전이표를 강제해야 합니다.

캠페인

draft ──→ submitted ──→ reviewing ──→ scheduled ──→ running ──→ completed
                    ↘             ↘                      ↕
                      canceled ←────────────────────── paused

running · scheduled ──→ canceled · refunded
completed · refunded ──→ (종료 상태 — 전이 불가)
현재 상태허용 전이사유
draftsubmitted, canceled—
submittedreviewing, scheduled, canceled반려 시 필수
reviewingscheduled, canceled반려 시 필수
scheduledrunning, canceled, refunded취소 시 필수
runningpaused, completed, canceled, refunded중단 시 필수
pausedrunning, canceled, refunded—
completedrefunded필수
canceled · refunded—종료

그 외

대상전이
충전 요청pending → approved · rejected  (종료)
주문paid → refunded · partial_refund  (환급 트랜잭션 동반)
배정assigned → in_progress → submitted → approved · rejected
정산pending → processing → completed  (역방향 불가)
문의open → in_progress → answered → won · closed
