# 토스 디자인 시스템(TDS) 적용 — 목업 리테마

`blueegg-live-share.html`(운영 실측 목업, 화면 103개)에 토스 디자인 시스템을 입힌 결과물과 그 근거.

| | |
|---|---|
| 입력 | `blueegg-live-share.html` — 원본, 수정하지 않음 |
| 출력 | `blueegg-live-share.toss.html` |
| 생성기 | `tools/toss_retheme.py` (+ `tools/toss_palette.py`) |
| 스펙 | design.md (토스 / TDS), 2026-08-22 |

재생성은 `python3 tools/toss_retheme.py`. 출력 파일을 직접 고치지 말고 생성기를 고칠 것.

## 적용 방식

목업의 색은 전부 `:root`의 `--*-rgb` 변수를 타고 돈다. 그래서 **토큰 레이어만 갈아끼우면 103개 화면이 동시에 바뀐다.** 토큰 밖에 색이 박혀 있는 자리(그라디언트, arbitrary hex 클래스, 인라인 style)만 따로 처리했다.

원본 CSS는 건드리지 않고, `</head>` 직전에 `<style id="toss-theme">` 한 벌을 덧붙여 같은 특정도(specificity)로 뒤에서 이긴다. 되돌리려면 그 블록만 지우면 된다.

| 처리 | 건수 |
|---|---|
| `:root` 토큰 재정의 | 19 |
| 색을 직접 박은 CSS 규칙 오버라이드 | 422 (색 선언 467건) |
| 그라디언트 평탄화 — CSS 클래스 | 24 |
| 그라디언트 평탄화 — 인라인 `style` | 200 |

## 색: OKLCH → sRGB

스펙의 색 토큰은 OKLCH로 기술돼 있어 sRGB로 변환했다(`tools/toss_palette.py`). 변환기는 스펙이 공식 hex로 명시한 앵커로 검증했다.

**단, `blue-500`만은 변환값이 아니라 공식 hex를 쓴다.** 스펙 표기 `oklch(0.624 0.176 254)`를 변환하면 `#2887ee`가 나오는데, 스펙이 미니앱 브랜딩 가이드의 공식값으로 명시한 것은 `#3182F6`이다. `#3182F6`의 실제 OKLCH는 `0.6201 0.1906 258.2` — **스펙의 OKLCH 표기가 반올림값**이다. 브랜드 앵커는 공식 hex를 따르는 게 맞다.

### 임의 색의 스냅 규칙

토큰 밖에 박힌 색 수백 개를 손으로 매핑하는 대신, OKLab 위에서 TDS 토큰으로 떨어뜨렸다.

1. **중성색 판정** — TDS의 회색은 순수 무채색이 아니라 cool-blue로 기운 중성색이다(`grey-900`부터가 C=.030). 단순 채도 컷으로는 회색과 옅은 색조가 안 갈린다. 그래서 **회색 hue 대역(235~275°) 안이면 채도 .045까지 회색으로**, 대역 밖이면 .012까지만 회색으로 본다.
2. **hue 스냅** — 유채색은 TDS 시맨틱 hue(blue 254 / green 154 / red 22 / orange 56 / yellow 86) 중 가장 가까운 쪽으로 끌어온다.
3. **명도 단계** — L<0.40이면 grey-900(TDS의 유일한 dark surface). 그 외는 hue별 base step.
4. **역할 인지** — 텍스트 색은 반드시 읽혀야 하므로 별도 처리한다(아래 편차 참조).

## 형태·타이포

- **라운드** — 목업의 10/14/18/22px를 TDS 사다리로 한 칸씩 올렸다: `radius-m 12` / `radius-xl 16` / `radius-2xl 20` / `radius-3xl 24`. 스펙이 TDS를 "프로덕션에서 가장 둥근 모바일 시스템 중 하나"로 규정한다.
- **그림자** — navy-900 베이스 저알파 4단(shadow-1/2/3/toast)으로 교체. floating 표면에만 등장하고 평면이 기본이다.
- **굵기** — 목업은 400~800을 쓰는데 TDS 램프는 400/500/600/700 네 단이다. `extrabold 800→700`, `bold 700→600`, `semibold 600→500`으로 접었다.
- **자간** — TDS type ramp의 letterSpacing을 크기 구간으로 옮겼다: ≥22px `-.02em` / 19~21 `-.015em` / 17~18 `-.01em` / 14~16 `-.005em` / ≤13.5 `0`.
- **크기** — 목업의 34가지 크기를 TDS type ramp 위로 한 단씩 올렸다. 아래 표 참조.
- **폰트** — 손댈 게 없다. 목업이 이미 `Pretendard Variable`을 쓰고, 스펙도 Toss Product Sans(외부 재배포 금지)의 대체로 Pretendard를 명시한다.

## 타입 스케일

목업은 밀집 데스크탑 대시보드라 글씨가 작았다 — 11.5px가 3,063회, 11px 이하가 약 2,000회 쓰였다. TDS의 최소 크기는 caption-s 11px다. 34가지 크기를 TDS ramp 위로 한 단씩 올렸다.

| 현재 | → | TDS |
|---|---|---|
| 7 · 8 · 8.5 · 9 | 11 | caption-s |
| 9.5 · 10 · 10.5 | 12 | caption |
| 11 · 11.5 · 12 | 13 | body-3 / label-s |
| 12.5 · 13 · 13.5 | 15 | body-2 / label-m |
| 14 · 14.5 · 15 | 17 | body-1 / label-l |
| 15.5 · 16 · 17 | 18 | title-1 |
| 18 · 19 | 20 | h4 |
| 20 | 22 | h3 |
| 22 · 23 | 24 | h2 |
| 24 이상 | 그대로 | 이미 충분히 크고 스탯 카드 레이아웃 위험이 크다 |

작은 글씨일수록 많이 키운다(9px → 11px, +22%). 본문은 +13~15%다. 매핑은 **단조 비감소**라 어떤 크기도 작아지지 않는다.

이름 사이즈(`text-xs`~`text-xl`)는 `line-height`를 함께 들고 있어 같은 비율로 옮겼다. 반응형 변형(`max-[700px]:text-[19px]` 등 6쌍)은 부분일치 셀렉터에 함께 걸리므로 `:not([class*=":text-[Npx]"])`로 제외하고 자기 미디어쿼리 안에 따로 냈다. 자간은 **키운 뒤 크기** 기준으로 다시 계산한다.

`text-[Npx]`는 `font-size`만 잡고 line-height는 `normal`이라 줄간격은 비례로 따라온다. 명시적 `leading-[n]`도 무단위 비율이라 마찬가지다.

### 레이아웃 영향 검증

1400px에서 59개 라우트를 전수 측정했다.

- **페이지 가로 넘침 0건.** 넓은 표는 원래부터 `overflow-x:auto` 컨테이너로 설계돼 있고, 스크롤 폭이 원본과 **완전히 동일하다**(`admin/purchases` 1098/1524). 표 너비는 고정 `min-w-[1380px]`와 컬럼 폭이 정하지 글씨가 늘리지 않는다.
- **세로 클리핑 회귀 0건.** `platform/perf`의 아이폰 베젤 프레임(456 안에 1521)은 원본에도 있는 의도된 잘림이다.

한 건 회귀가 있었고 고쳤다 — `platform/content_branding`의 명함 목업 카드가 인라인 88px 고정 안에서 101px이 되어 잘렸다. **300×360 장식 스테이지(브랜딩·상세페이지·영상 화면) 내부는 UI 텍스트가 아니라 그림의 일부**라 확대 대상에서 제외했다.

사이드바에서 `포인트 충전(카드) 요청 - 현재 사용 불가`가 다시 잘린다 — 글씨가 커진 만큼 예상된 결과이며 `title` 속성이 툴팁을 준다.


## 좌측 네비게이션

레일은 별도로 손봤다. 셀렉터는 `aside[class*="min-[901px]:w-60"]` 안으로만 한정한다 — 본문에 화면 안쪽 사이드 패널로 쓰이는 `<aside>`가 10개 더 있다.

| 고친 것 | 원래 상태 |
|---|---|
| **선택 상태** | 런타임이 활성 링크에 `aria-current="page"`를 붙이는데 **받는 스타일이 없었다.** 목업 패치 CSS의 `font-weight:700`이 전부라 어느 화면인지 사실상 안 보였다. TDS chip의 brand 변형(`bg-brand-weak` + `text-brand`)을 적용했고, 아이콘은 `currentColor`를 상속해 함께 파랗게 된다 |
| **hover** | 어드민은 회색, 플랫폼은 브랜드색이라 셸마다 달랐다. 중립 회색으로 통일하고 브랜드색은 선택 상태에만 남겼다 (화면당 단일 강조색) |
| **행 여백** | `padding-left: 0`이라 hover 배경이 아이콘에 딱 붙었다. `8px 10px` + 라운드 10px(TDS S 버튼 값), 높이 34px |
| **빈 선행 슬롯** | 쓰이지 않는 18px 슬롯이 어드민 26개 행 전부에 붙어 라벨을 잘랐다("포인트 충전(카드) 요청 - 현재…"). 제거해 26px를 되찾았다 |
| **트리 위계** | 플랫폼에서 자식 행이 부모 아이콘보다 **왼쪽**에 놓여 위계가 뒤집혀 있었다. 위 슬롯 제거로 바로 섰다 |
| **그룹 라벨** | `10px / 800 / 자간 .07em` 마이크로 캡스 → caption-s 규격(`11px / 600 / 자간 0`). TDS는 넓은 자간 마이크로 캡스를 쓰지 않는다 |
| **그룹 토글** | 굵기 폴딩 뒤 리프와 똑같이 500이 되어 평평해졌다. 600 + `fg-primary`로 한 단 올렸다 |
| **아이콘** | 15px(사다리 밖) → 16px, stroke 1.8 → 1.5 (TDS: 24px 그리드 기준 1.5~1.67) |
| **즐겨찾기 별** | 앰버 hover가 스냅으로 탁한 갈색(`#994b00`)이 됐다. 브랜드색으로 되돌렸다 |

### 내비게이션 버튼 배선 (동작 수정)

목업 런타임은 `a[href^="/"]` 클릭만 가로채 해시로 옮긴다. 그런데 홈·어드민 이동 같은 컨트롤은 실제 앱에서 `<button>` + onClick 이라 링크 가로채기에 걸리지 않고, 런타임의 `wireNavGroups`도 이들을 명시적으로 건너뛰며(`title`에 '어드민'·'플랫폼'이 들어가면 return), `wireNavButtons`는 `main` 안에서만 돈다. **그래서 원본 목업에서 홈 버튼은 눌러도 아무 일이 없었다.**

`#root`는 해시가 바뀔 때마다 `innerHTML`째로 다시 그려져 직접 건 리스너가 날아간다. 그래서 `document`에 위임(delegation)으로 걸었다 — `<script id="toss-nav-fix">`.

| 컨트롤 | 위치 | 목적지 |
|---|---|---|
| `어드민 홈` | 어드민 헤더 로고 · 사이드바 홈 | `#/admin/` |
| `어드민 페이지로 이동` | 플랫폼 사이드바 하단 | `#/admin/` |
| `홈(런처)으로` | 플랫폼 헤더 로고 | `#/platform/` |
| `홈으로` | 플랫폼 사이드바 홈 | `#/platform/` |
| `클릭하면 포인트 충전` | 플랫폼 헤더 포인트 pill | `#/platform/charge` |
| `최상단으로` | 우측 플로팅 | 스크롤 top |

이미 그 화면에 있으면 `hashchange`가 안 나 모바일 드로어가 열린 채 남으므로, 해시를 바꾸기 전에 드로어를 닫는다.

**배선하지 않은 것과 이유**

- `장바구니` — `aria-expanded` + `data-cart-anchor`를 가진 팝오버 트리거다. 여는 패널이 수집되지 않아 목적지를 지어낼 수 없다.
- `알림` — 드롭다운인지 페이지 이동인지 실측으로 갈리지 않는다 (`admin/alerts` · `platform/alerts` 화면은 존재한다).
- `다크 모드` — 이 목업에 다크 테마가 없다.
- `사이드바 접기/펴기` — 접힌 레일의 DOM이 수집되지 않았다.


### 아이콘 색 주입 제거

레일 아이콘 11개가 SVG `stroke` 속성에 색을 직접 물고 있었다(핑크·틸·남색 등). 속성이라 CSS 리테마를 타지 않아 토스 팔레트와 어긋나 있었다. 스펙이 이 경우를 직접 다룬다 — **"모든 아이콘은 `currentColor`를 상속한다 — 외부 컬러 직접 주입은 금지다."** 그대로 `currentColor`로 바꿨다.

**예외는 제3자 브랜드 마크 2종이다.** `#03C75A`(네이버), `#C1122F`(쿠팡)는 그 브랜드의 식별색이라 토스 팔레트로 옮기면 무엇을 가리키는 항목인지가 사라진다. 스펙도 브랜드 혼동 금지를 요구하므로 그대로 뒀다.

스냅으로 처리하지 않은 이유도 있다. 자체 서비스 마크 5개를 팔레트에 밀어 넣으면 브랜딩·홈페이지가 같은 파랑, 이미지·영상이 같은 빨강으로 뭉개져 구분이 사라진다 — 아래 편차 2번과 같은 문제다.

## 남은 것 — SVG 속성에 박힌 색 214개

리테마는 CSS와 인라인 `style`을 처리한다. **SVG의 `stroke` / `fill` 속성에 박힌 색은 대상이 아니다.** 레일은 위에서 정리했지만 화면 본문에는 17종 214개가 남아 있다.

가장 많은 것이 `#2e6be0` 42개 — 리테마 이전의 옛 BlueEgg 브랜드 블루다. 토스 `blue-500`(`#3182F6`)과 hue는 거의 같지만 명도가 한 단 낮아(L .556 vs .620) 나란히 놓이면 두 가지 파랑으로 읽힌다. 그다음은 `#6366f1`(인디고) 33개, `#0ea5e9`(스카이) 21개 등 콘텐츠·랜딩 화면의 장식 아이콘이다.

`#03c75a`(네이버) 24개는 제3자 브랜드색이라 남기는 게 맞다.

정리하려면 레일에 쓴 것과 같은 방식(브랜드색 keep-list + 나머지 `currentColor` 또는 팔레트 스냅)을 본문까지 확장하면 된다. 별도 판단이 필요해 이번엔 하지 않았다.

## 편차 — 스펙대로 못 한 것과 그 이유

1. ~~본문 크기를 15px로 올리지 않았다.~~ **해소됨** — 위 「타입 스케일」 참조. 처음에는 TDS 램프가 mobile-first라 밀집 데스크탑 대시보드에 그대로 밀면 화면이 깨진다고 보고 크기를 유지했으나, 요청에 따라 램프 위로 한 단씩 올렸다. 59개 라우트 전수 측정 결과 가로 넘침·세로 클리핑 회귀는 없었다.

2. **보라·틸·핑크는 TDS에 없어 파랑으로 통합했다.** `혼합` 배지의 보라, `--teal`, 랜딩의 핑크가 전부 blue-500 계열로 갔다. "한 화면에 강조색을 둘 이상 두지 않는다"는 규율에는 맞지만, **`혼합` 배지와 `리뷰` 배지가 같은 파랑이 되어 구분이 사라졌다.** 카테고리 색 구분이 필요하면 별도 결정이 필요하다.

3. **노랑을 역할에 따라 갈랐다.** 스펙은 노랑을 일러스트 전용으로 두고 표면 색으로 쓰지 않는다. 그런데 목업은 서비스 태그에 앰버 텍스트·배경·보더를 쓴다. 채워진 배지(흰 텍스트)는 시맨틱 warning fill인 `orange-500`으로, 텍스트는 같은 hue의 어두운 파생 step `#994b00`으로 내렸다. **`orange-500` 위의 흰 텍스트는 대비 약 2.6:1로 낮다** — 원래 스펙도 이 조합을 문서화하지 않는다.

4. **washed 배지 배경은 파생값이다.** 스펙 Known Gaps가 hue별 washed step(blue-100~400, red-50~400 등)은 미공개라고 밝히고, red badge를 `oklch(0.940 0.040 18)`로 추정 제시한다. 그 방식 그대로 base hue에서 명도만 끌어올려 wash(L .955) / wash 보더(L .900)를 만들었다. `--brand-soft2`(blue-100)도 같은 파생값이다.

5. **`platform/cafe`는 손대지 않았다.** 제3자 사이트(네이버 카페)를 흉내 내는 표면이다. 스펙 자체가 "사용자가 당신의 브랜드를 토스와 혼동해서는 안 된다"며 브랜드 분리를 요구하므로, 이 화면은 자기 팔레트를 유지하는 게 맞다.

6. **다크 모드는 만들지 않았다.** 원본 목업에 다크 테마가 없고, 스펙도 Known Gaps에서 **다크 모드 alias 테이블이 미공개**라고 밝힌다. 근거 없이 지어낼 자리가 아니다.

7. **Tossface 이모지 폰트는 넣지 않았다.** 목업은 오프라인에서 열리는 단일 파일이라 외부 웹폰트를 걸 수 없다.

## 카피

스펙의 Voice 규칙(해요체, "Navigating error", 마케팅 과장 금지, 버튼은 일어날 일을 직접 말한다)은 **이번 작업 범위 밖이다.** 이번엔 시각 언어만 입혔다. 목업 카피는 운영 앱에서 뽑은 실측 문안이라, 손대려면 별도 판단이 필요하다.
