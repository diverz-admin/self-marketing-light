# BlueEgg Light 적용 — 목업 리테마

`blueegg-live-share.html`(운영 실측 목업, 화면 103개)에 운영 사이트의 라이트 디자인을 입힌 결과물과 그 근거.

| | |
|---|---|
| 입력 | `blueegg-live-share.html` — 원본, 수정하지 않음 |
| 출력 | `blueegg-live-share.light.html` |
| 생성기 | `tools/light_retheme.py` (+ `light_palette.py` · `light_home.py` · `light_icons.py`) |
| 레퍼런스 | https://self-marketing-light.vercel.app/marketing |

재생성은 `python3 tools/light_retheme.py`. 출력 파일을 직접 고치지 말고 생성기를 고칠 것.

토스 적용본(`blueegg-live-share.toss.html`)은 그대로 두었다. 두 벌은 서로 독립이다.

## 적용 방식

토스 리테마(`docs/TOSS-RETHEME.md`)와 같은 골격이다. 목업의 색은 전부 `:root`의 `--*-rgb` 변수를
타고 돌기 때문에 **토큰 레이어만 갈아끼우면 103개 화면이 동시에 바뀐다.** 원본 CSS는 건드리지 않고
`</head>` 직전에 `<style id="light-theme">` 한 벌을 덧붙여 같은 특정도로 뒤에서 이긴다.
되돌리려면 그 블록만 지우면 된다.

| 처리 | 건수 |
|---|---|
| `:root` 토큰 재정의 | 19 |
| 색을 직접 박은 CSS 규칙 오버라이드 | 406 (색 선언 451건) |
| CSS 그라디언트 리컬러 | 24 |
| 인라인 `style` 색 선언 | 522 |
| SVG `stroke`/`fill` 속성 | 168 |
| 대시보드 화면 재작성 | 1 (`platform/`) |

### 임의 색의 스냅 규칙

토큰 밖에 박힌 색 수백 개는 OKLab 위에서 레퍼런스 팔레트로 떨어뜨렸다.

1. **중성색 판정** — 이 팔레트의 회색도 순수 무채색이 아니라 navy로 기운 중성색이다
   (`text-strong` 자체가 C=.053). 그래서 **navy hue 대역(245~285°) 안이면 채도 .058까지 회색으로**,
   대역 밖이면 .014까지만 회색으로 본다. `navy-700`은 C=.117이라 이 컷에 안 걸린다.
2. **hue 스냅** — 유채색은 시맨틱 hue(blue 254 / cyan 211 / green 152 / amber 69 / red 23) 중
   가장 가까운 쪽으로 끌어온다.
3. **파랑의 명도 단계** — 이 디자인의 chrome은 navy 사다리로 간다.
   L<.29 `navy-900` / <.33 `navy-800` / <.60 `navy-700` / <.72 `accent-blue` / 그 위는 wash.
   경계 .60은 목업의 브랜드 블루 `#2e6be0`(L .556)이 `navy-700`으로 떨어지도록 잡은 값이다 —
   토큰을 타는 자리와 하드코딩된 자리가 같은 색이 되어야 한다.
4. **역할 인지** — 텍스트는 읽혀야 하므로 앰버·시안은 같은 hue의 어두운 파생 step으로 내린다.

## 토스 적용본과 다르게 한 것

세 가지는 **의도적으로 반대로** 했다. 토스 스펙의 규율이 아니라 이 레퍼런스의 규율을 따랐기 때문이다.

**1. 그라디언트를 평탄화하지 않는다.**
토스는 chrome에 그라디언트를 금지하지만 레퍼런스는 `--gradient-brand`를 실제로 쓴다
(히어로 카드, 배너, 프로필 카드). 그래서 스톱을 각각 스냅하고, **스톱이 전부 navy 사다리로
떨어지면 통째로 `var(--gradient-brand)`로 바꿔** 브랜드 그라디언트 하나로 수렴시켰다.
홈 배너 `linear-gradient(120deg,#2f6fe6,#1b49a8)`가 이 경로로 레퍼런스 히어로와 같은 네이비가 됐다.
반대로 캠페인 아바타 타일 `#3a8bd8→#1f5fae`는 스톱이 `accent-blue`와 `navy-700`으로 갈려
두 단 그라디언트를 유지한다.

**2. 아이콘의 색 주입을 걷어내지 않는다.**
토스 스펙은 "모든 아이콘은 `currentColor`를 상속한다"고 요구해서 레일 아이콘 11개를 단색으로 바꿨었다.
**레퍼런스는 반대로 서비스별 색을 유지한다** — 플레이스 그린 핀, 쇼핑백 그린, 쿠팡 레드, 네이버 그린이
레일에 그대로 살아 있다. 그래서 여기서는 색을 남기고 팔레트로 스냅만 했다.

이 결정 덕분에 **토스 적용본에서 남겨뒀던 본문 SVG 속성 색도 이번엔 처리했다.**
`stroke`/`fill` 속성은 CSS도 인라인 style도 아니라 리테마를 안 타던 자리다(토스 리테마는 214개를 남겼다).
아이콘 색을 죽이지 않는 이상 스냅해도 정보가 사라지지 않으므로 168건을 팔레트로 옮겼다.

**3. 타입 스케일을 올리지 않는다.**
토스 램프는 mobile-first라 밀집 데스크탑 대시보드에 맞춰 한 단씩 올려야 했다.
**레퍼런스는 같은 밀도의 데스크탑 대시보드**라 올릴 이유가 없다. 자간만 레퍼런스 규칙으로 맞췄다 —
본문 `-.01em`, 19px 이상 `-.03em`, 15~18px `-.02em`.

## 형태

- **라운드** — 레퍼런스 사다리 8/12/16/20/999 위로: `.rounded-sm` 12(입력·버튼) /
  `.rounded-md` 16(카드) / `.rounded-lg`·`.rounded-xl` 20(시트·배너).
- **그림자** — navy-900 베이스 저알파 3단(`--shadow-sm/md/lg`)으로 교체.
  카드 hover는 레퍼런스 `.card-hover` 규격(`border-strong` + `0 4px 16px #111d371a`)을 그대로 썼다.
- **굵기** — 레퍼런스는 500/600/700 세 단을 쓴다. 목업의 800만 700으로 접었다.
- **focus** — `2px solid #0d3473`, offset 2px. 입력 요소는 흰 배경 + 브랜드 보더 + 3px 링.
- **폰트** — 손댈 게 없다. 목업도 레퍼런스도 `Pretendard Variable`을 쓴다.

## 좌측 네비게이션

레퍼런스 레일의 규격을 그대로 옮겼다. **폭 260px**(`--sidebar-w`, 목업은 240이었다) /
행 높이 44px / 라운드 10px / 좌우 패딩 12px, 선택 상태는 `navy-100` 배경 +
`brand-primary` 텍스트 + 3px 좌측 바.

폭은 데스크탑 브레이크포인트(`min-width:901px`) 안에만 걸었다 — 그 아래는 모바일 드로어
(264px / `max-w:84vw`)라 건드리면 안 된다. 어드민·플랫폼 두 레일에 함께 적용된다.

원본은 활성 링크에 `aria-current="page"`를 붙이는데 받는 스타일이 없어 선택 상태가 사실상 안 보였다.
어드민 26개 행이 달고 있던 빈 18px 슬롯도 걷어내 라벨 폭을 되찾았다.
그룹 라벨은 넓은 자간 마이크로 캡스 대신 11px + 상단 헤어라인 구분선으로 바꿨다 — 레퍼런스 방식이다.

## 건드리지 않은 것

- **`platform/cafe`** — 제3자 사이트(네이버 카페)를 흉내 내는 표면이다. 이 화면의 `svcCafe` 팔레트와
  SVG 속성 색은 통째로 건너뛴다.
- **네이버 `#03C75A` · 쿠팡 `#C1122F`** — 그 브랜드의 식별색이라 팔레트로 옮기면
  무엇을 가리키는 항목인지가 사라진다. 스냅 대상에서 뺐다.
- **흰색·검정** — 알파 오버레이 용도라 스냅할 hue가 없다.

## 대시보드 레이아웃 — `tools/light_home.py`

색은 토큰 레이어로 끝났지만 **레이아웃은 마크업 문제**라 `#/platform/` 화면 한 벌을 새로 짰다.
원본 목업 화면에서 데이터를 뽑아 레퍼런스 구조에 다시 담는 방식이라, 목업을 다시 수집해도
공지·캠페인·주문 내용이 자동으로 따라온다. **지어낸 데이터는 없다.**

```
main
 ├ 본문 칼럼 (flex-1, px 40 / pt 40, 세로 gap 24)
 │   ├ 인사말 (좌측 정렬 한 줄)
 │   ├ section 2열 gap 20 — [공지사항]         [다크 히어로]
 │   └ section 2열 gap 20 — [운영중인 캠페인]   [순위 추적]
 └ 우측 레일 320px (border-left, bg canvas)
     └ [즐겨찾기]  [실시간 주문 현황]
```

### 사이드바

셸에 들어가므로 플랫폼 화면 전체에 적용된다 — 레퍼런스도 전역 요소다. **어드민 셸은 건드리지
않았다.** 어드민 레일은 트리 모양이 달라 같은 규칙을 쓰면 안 되므로, 플랫폼 `<aside>` 에만
`be-rail-nav` 클래스를 붙여 갈랐다.

| | |
|---|---|
| 폭 | 260px (`--sidebar-w`, 목업은 240이었다). 데스크탑 브레이크포인트 안에만 걸었다 — 그 아래는 모바일 드로어(264 / `max-w:84vw`)다 |
| 프로필 카드 | 레일 **상단**의 네이비 그라디언트 카드 — 아바타·이름·티어 배지·사용 가능 포인트·만료 예정 광고·충전 버튼·바로가기 2줄 |
| 「홈」 행 | 원본은 라벨 없는 아이콘 버튼 하나였다. 아이콘 + 라벨 + 셰브런 행으로 바꾸고 선택 상태를 받게 했다 |
| 섹션 라벨 | 최상위 그룹 머리를 불릿 라벨(13px + 상단 헤어라인)로 접고 그 아래 행을 평평하게 폈다 |
| 채널 그룹 | 접힌 상태로 시작 — 원본은 셸을 펼친 상태로 수집해 리프 20여 개가 다 펼쳐져 있었다 |
| 타이포 | 나브 행 15 / 3단째 리프 14 / 섹션 라벨 13 / 홈 15. 행 높이 44, 아이콘 19 |

채널 그룹을 접을 때 CSS 로 숨기면 안 된다. 런타임 토글(`wireNavGroups`)이
`panel.style.display === 'none'` 으로 상태를 판정하므로, 인라인 style 이 없으면 **첫 클릭이
헛돈다.** 그래서 인라인 `display:none` 을 직접 박고 화살표의 `rotate-90` 도 같이 뗐다.

⚠️ 프로필 카드 안의 링크는 리테마 §12 의 레일 행 규칙(`aside[class*=…] a[href^="/"]`,
특정도 (0,2,2))에 걸린다. 클래스만으로는 못 이겨서 `[href]` 를 붙여 (0,3,1) 로 올렸다.

**시안 값을 그대로 옮긴 자리** — 목업에 데이터가 없다. `TIER` / `EXPIRING` 상수 두 개에
모아 뒀으니 실데이터가 생기면 거기만 바꾸면 된다. 티어 배지 `Bronze`, `만료 예정 광고 0 개`,
그리고 `My SNS 대시보드` 는 대응 라우트가 없어 **링크를 걸지 않았다**.

### 왜 `be-*` 클래스인가

목업 CSS는 **컴파일된 Tailwind**라 거기 없는 유틸리티 클래스를 새로 쓰면 아무 일도 하지 않는다.
그래서 이 화면만 `be-*` 클래스로 짓고 `HOME_CSS`에서 직접 정의했다. 색은 리테마 토큰을 타므로
팔레트를 바꾸면 이 화면도 같이 바뀐다.

아이콘은 **레퍼런스에서 그대로 가져왔다**(`tools/light_icons.py`). BlueEgg 자사 자산이라
팔레트 스냅을 태우지 않고 원본 값을 쓴다 — 그래서 대시보드 재작성은 파이프라인의
**마지막 단계**에서 주입된다.

### 레퍼런스대로 못 한 것

**우측 레일이 3장이 아니라 2장이다.** 레퍼런스는 고객지원 상담 / 트래픽 제휴 / 신규 상품
프로모 카드 3장을 둔다. 목업에 그 문안이 없어 지어내지 않았다.

**「고객 인터뷰」가 아니라 「이벤트 · 소식」이다.** 레퍼런스는 이 자리에 고객 후기 인용을 돌린다.
목업에는 후기 데이터가 없고 배너 3장이 있어 그걸 넣었다. 카드 구조(아이브로우 필 · 인용부호 ·
큰 헤드라인 · 도트 · 하단 3-타일)는 레퍼런스 그대로다.

| 자리 | 값 | 근거 |
|---|---|---|
| 지면 | `#ffffff` | 회색 캔버스가 아니라 흰색이다 |
| 카드 헤어라인 | `#e1e4e8` | |
| 네이비 면 | `linear-gradient(135deg,#324371,#1a274a)` | 실측 모서리 TL `#324371` / TR `#212f55` / BL `#2b3b66` / BR `#1a274a` |
| 네이비 위 본문 | `rgba(255,255,255,.66)` | 실측 `#b5bac8` 을 배경에 역산 |
| 고스트 숫자 | `#d3d5d7` | |
| 헤딩·카드 제목 | `#0d1522` | 브랜드 네이비가 아니라 거의 검정이다 |
| 아이브로우 | `#4384ca` | |
| 원형 화살표 | 배경 `#a3cffd` · 화살표 `#0d1522` | 어두운 원이 아니라 **하늘색 원에 진한 화살표**다 |
| 라운드 | 12px | 모서리 호 실측 (x 31→43) |
| 카드 간격 | 20px | 행 간격 실측 (y 392→413) |

**라운드는 12px이라 기존 16px과 큰 차이가 아니었다.** 처음에 시안을 보고 4~6px로 읽었는데
실측하니 12px이다. 시안이 "각져 보이는" 인상은 라운드가 아니라 **분할 면**에서 온다.

### 적용 범위

`.be-ref2` 클래스를 대상 화면의 `<main>` 에만 붙여 스코프를 가른다 — 어드민·캠페인 관리 등
업무 화면 90여 개는 이 규칙을 안 탄다.

대상: 대시보드(`platform/`) + 랜딩 화면 8개(추가 서비스 인덱스 · 홈페이지 제작 · Total 브랜딩 ·
상세페이지 · 영상 · SA광고 최적화 · 광고비 환급 · 카페 침투). 탭 변형 템플릿까지 11개.

네이비 면은 **변수 하나만 갈아끼워** 옮겼다 — 리테마가 chrome 그라디언트를 전부
`var(--gradient-brand)` 로 수렴시켜 뒀기 때문에, `.be-ref2{--gradient-brand:…}` 한 줄이면
이 화면들의 네이비 면이 전부 시안 값이 된다.

### 분할 카드

`content_home` 의 「5단계 제작 프로세스」는 번호 + 제목 + 설명 구조라 시안 카드에 그대로 얹힌다.
왼쪽 = 고스트 숫자 + 제목, 오른쪽 = 네이비 면 + 설명, 이음새에 하늘색 원형 화살표.
2열 그리드로 5장이 들어간다.

파싱은 헤더를 찾은 뒤 스텝 카드를 **연속으로** 물어 나간다. `(.*?)</div></div>` 로 한 번에
잡으려 하면 첫 카드에서 끊긴다 — 카드 안에도 닫는 div 가 연달아 나오기 때문이다.

**시안과 다른 점** — 시안은 네이비 면에 굵은 제목 + 설명을 함께 둔다(문제 → 해결 쌍).
목업 스텝 데이터는 제목이 하나뿐이라 왼쪽에 제목, 오른쪽에 설명만 두었다. 없는 제목을
지어내지 않았다.

### 서비스 강조색은 건드리지 않았다

랜딩 화면은 서비스마다 자기 강조색을 갖는다 — 홈페이지 스카이 / 브랜딩 인디고 ·
골드 / 이미지 핑크 / 영상 오렌지 / 카페 네이버 그린. **그 색까지 시안의 `#4384ca` 로 통일하면
7개 서비스가 한 덩어리로 뭉개진다.** 지면·면·헤어라인·라운드만 옮기고 강조색은 남겼다.
(토스 적용본에서 「혼합」 배지와 「리뷰」 배지가 같은 파랑이 되어 구분이 사라졌던 것과 같은 문제다.)

## 되돌린 시도 — 세 번째·다섯 번째 시안

두 시안을 대시보드에 입혔다가 **요청에 따라 되돌렸다.** 다시 하려면 아래가 그때 한 일이다.

**세 번째 시안(순위 추적 · 깔끔한 레이아웃)** — 색은 그대로 두고 배치만 옮겼었다.
가운데 정렬 헤더(상태 pill + 2줄 헤딩), 그림자 없는 평면 카드, 여백 확대,
안쪽 블록을 옅은 회색 면으로, 칩 전부 알약형(999px).

**다섯 번째 시안(충전 페이지)** — 구조를 바꿨었다. 상단 스탯 스트립(카드 한 장을 세로
헤어라인으로 4칸 나눠 KPI), 우측 레일 제거 후 단일 칼럼, 실시간 주문을 하단 전체 폭 카드로.

**일곱 번째 시안(전체 대시보드)** — 가장 컸다. 사이드바를 짙은 네이비(`#071e52`, 활성 행
`#0b3695`)로 뒤집고 프로필 블록을 하단 고정으로 내렸다. 본문은 인사말(이름 파랑 `#0048ec`
2줄) + 공지 목록(불릿 + 분류 칩) + 히어로(노란 밑줄 `#fecb39` · 원형 화살표 `#cbdcfd` ·
장식 막대 · KPI 진행바) + 캠페인 **표** + 순위 탭/델타 칩, 우측 레일은 실시간 알림 +
옅은 파랑 카드(`#f3f8fe`)였다. 색은 시안 이미지에서 직접 샘플링한 값이다.

⚠️ `tools/` 는 git 에 없어서 되돌릴 때 **스냅샷이 아니라 이 문서의 사양대로 다시 지었다.**
앞으로 이런 왕복이 더 있으면 `tools/` 를 커밋해 두는 게 낫다.

되돌린 뒤 상태를 실측으로 확인했다 — 인사말 좌측 정렬 22px / 레일 320px /
스탯 스트립·가운데 헤더 0개 / 배지 라운드 8px · 탭 12px / 카드 그림자 복원 / 가로 넘침 0.

## 남은 것

**분할 카드는 `content_home` 한 곳에만 들어갔다.** 다른 랜딩 화면에도 번호 섹션이 있지만
화면마다 마크업이 달라(`0X` 토큰만 같고 구조가 제각각) 한 벌의 파서로는 못 잡는다.
필요하면 화면별로 하나씩 처리해야 한다.

**대시보드 밖 화면은 레이아웃을 손대지 않았다.** 리테마(색·라운드·그림자·자간)만 입혀져 있다.
`platform/` 홈 한 화면만 레퍼런스 구조로 다시 짰다.

**섹션 타이틀의 컬러 left-rail이 남은 화면에 그대로 있다.** 레퍼런스는 색 막대 대신 아이콘 타일을
쓴다 — 대시보드는 그렇게 바꿨지만 나머지 화면은 마크업 구조라 리테마 범위 밖이다.

## 리테마가 만들지 않은 문제

`platform/perf` 히어로의 아이브로우 "NAVER SA / 검색광고 최적화"가 네이비 배경 위에서 안 읽힌다.
**원본 목업에서도 같다** — 어두운 히어로에 `text-ink`(거의 검정)를 쓴 자리다.
어두운 표면을 셀렉터로 일반화해 잡을 방법이 마땅치 않아 이번엔 손대지 않았다.
